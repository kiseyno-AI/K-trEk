# Grid pagination — local v0.2.1

The grid displays at most 15 activities per page. A native navigation row shows `Page 1 of N` and Previous/Next icon buttons only when the active category has more than 15 cards. First/last navigation is disabled at the boundaries. Categories reset to page 1 after the outgoing cards leave; a list-to-grid switch opens the page containing the focused activity. Detail return retains the current page and its native scroll offset. The existing swipe list is unchanged.

The implementation stays in the canonical ActivityExplorer with one pure activityPage helper; no new UI dependency, animation owner, API, database or timer. The bundled template Pagination uses anchor links/Base UI/Tailwind variants; these controls change local state and reuse the trip's existing native buttons and tokens instead. Page status is a polite atomic live region. Native controls retain keyboard activation and focus rings.

Files: app/activity-explorer.tsx, app/globals.css, lib/activity-pagination.ts, tests/activity-pagination.test.mjs, package.json/package-lock.json and the UI registry/report. No production build or deployment.

Before implementation, the 1280×720 all-category grid mounted114cards, with renderer submission sampled0.10ms and one existing GPU owner (10buffers,5programs,4textures). Pagination reuses the same finite right-side card entrance, visibility pause, reduced-motion finish and cancellation. A page switch resets only the grid pane, and only viewport-intersecting cards are animated. Target budget is at most15gridcards, at most5listcards, and no new GPU objects, polling or frame loop. Unit coverage exercises16items, the114itemlastpage, an exact15itemcategory, a shrunken result and an empty list. Browser verification results are recorded below after integration.
