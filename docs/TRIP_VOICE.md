# KTravel voice integration

## Current release scope: local only

The owner explicitly requested local-only voice after the first public trial. Keep future voice changes local until the owner explicitly requests a shared release. The current shared site has no voice control; its proxy denies `/ktravel/api/voice` and `/ktravel/trip/voice` assets. The page and route also use the same loopback-host gate, preferring the proxy’s canonical `x-forwarded-host` over its loopback upstream Host. A direct public-origin request is rejected before authentication or paid provider calls. Local development is `http://localhost:3000`; the loopback production preview on4330also remains available. The shared site’s existing account/activity behavior is retained.

The English AI travel host is opt-in. Turn Voice on before signing in for a welcome, or enable it after signing in. Successful favorite additions and vote draft additions can play a short reaction; removals and ordinary browsing stay quiet. Visitors can explore without synthesis. The existing trip session supplies the name. Every member receives a general named Korea welcome; personal relationships and unrelated private facts are not part of the greeting or its agent input.

## Server contract

`POST /api/voice` accepts only `{event:"greeting"}` or `{event:"selection",activityId:"published-id"}`. It requires a current trip session, the exact website Origin, JSON and at most1024bytes. The selected English activity title comes from the database. The browser cannot supply a name, prompt, agent, voice, URL or credentials.

Personalized welcomes send an approved line to the loopback OpenClaw Responses endpoint, hardcoding `openclaw/ktravel-voice` and fresh independent requests. The dedicated agent uses the already configured `openai/gpt-5.6-luna` model with thinking and reasoning disabled; at most30words/200characters are requested. The agent has a two-second budget before the approved line is used, so cold inference cannot hold the greeting indefinitely. It accepts only a completed assistant response of at most300characters. Agent failure uses the approved line. It then calls ElevenLabs `eleven_flash_v2_5` with a five-second budget, English and the configured account-accessible voice. Success is a complete MP3 up to512KiB with a percent-encoded transcript header and an `openclaw` or `template` source header. Failure is a sanitized JSON message with optional approved text. No provider diagnostic is exposed.

An isolate admits at most two generations. Persistent existing authentication-limit buckets allow six new clips/member/five minutes and100globally/hour. Eight clips at most are cached for15minutes, limiting retained audio to4MiB. Replaying an existing clip does not synthesize again. The normal selection UI uses the pre-generated public `trip/voice/excellent-choice.mp3` instead of a paid event call. Its generic English transcript contains no name or private context. The player fetches it once while enabled and retains a single bounded Blob for subsequent synchronous native playback; mute/disposal clears it. The source manifest is next to the MP3. The authenticated event endpoint still accepts selection events. The public proxy now denies this experimental API and its static audio directory entirely. The player and browser lifecycle are documented in [TRIP_VOICE_UI.md](TRIP_VOICE_UI.md).
